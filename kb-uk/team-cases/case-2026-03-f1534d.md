1. Доступны следующие параметры для передачи в трекинговой ссылке:
sub_id={sub_id_1}
sub_id_2={sub_id_2}
sub_id_3={sub_id_3}
sub_id_4={sub_id_4}
sub_id_5={sub_id_5}
click_id={click_id}

2. В постбеках используются макросы:

##CLICK_ID## – идентификатор, полученный от CPA партнера;
##POSTBACK_ID## – внутренний ID постбека. Дополнительная переменная, всегда уникальна для каждого постбека. Поможет партнеру получить уникальное доп. значение по определенному ивенту с одинаковым click_id (например, доход по RevShare по одному и тому же игроку в разные дни);
##USER_ID## – ID записи в SiteUser (ID игрока на бренде);
##TRANS_ID## – уникальный ID игрока на платформе;
##IP_REG## – IP регистрации игрока (передается в формате: IP целиком);
##GEO_REG## – страна регистрации игрока (двухбуквенное значение, пример: "NL" для Netherlands);
##FD_AMOUNT## – сумма первого депозита игрока;
##RD_AMOUNT## – сумма повторных депозитов игрока;
##SITE_ID## – ID бренда;
##CPA_AMOUNT## – сумма, начисленная партнеру по CPA офферу;
##SUB_ID## – сабайди (он же трекер рефкода);
##SUB_ID_2## – дополнительный множественный сабайди;
##SUB_ID_3## – дополнительный множественный сабайди;
##SUB_ID_4## – дополнительный множественный сабайди;
##SUB_ID_5## – дополнительный множественный сабайди;
##RS_AMOUNT## – сумма, начисленная партнеру по RevShare. Отправляется раз в сутки, в момент создания начисления за прошлый день. Отправляется только для события "Доход по RevShare (RS)".

3. События для постбеков:
- Регистрация (REG);
- Первый депозит (FD);
- Повторный депозит (RD) – повторные депозиты RD (FD в этом событии не отправляется). События для CPA и гибридных офферов:
- Квалификация (CPA Hold);
- Подтверждение (CPA Approve);
- Отказ (CPA Reject).
События для REVSHARE и гибридных офферов:
- Доход по RevShare (RS).

Список все макросов также доступен при добавлении шаблонов постбека. В кабинете партнера список событий ограничен, в админ-панели весь список.
