## 1. Сторінка "Обнулення негативних балансів"

Функціонал дозволяє обнулити негативні баланси за RevShare для вебмайстрів.

Обнулення балансу обов’язково має бути погоджене з керівником!

Посилання на сторінку:https://aff.ltd/admin/new/negative-balance-rules

Розташування: розділ "Доходи" → "Обнулення негативних балансів".

На сторінці доступна можливість створення правил для обнулення та перегляду логу обнулень.

[image: https://d295evyo48.ucarecd.net/8202e6d6-bfb7-4018-b517-36d76c925ad1/Group_11.png]

1.1. Таб "АКТИВНІ ПРАВИЛА"

У межах таба показана таблиця з усіма активними правилами обнулення балансів.

Також виведені кнопки: "+ Створити правило" та "+ Створити ручне обнулення" (опис нижче).

Доступний пошук вебмайстра за ID або Email. Наявні фільтри: Локація, Група вебмайстрів, Менеджер, Створив / Змінив.

Сценарії, якщо немає активних правил за умовами пошуку або фільтрації:

- Якщо немає правил і їх ніколи не було, буде зазначено, що у вебмайстра немає активних або видалених правил обнулення;
- Якщо колись існували правила обнулення для вебмайстра, а зараз їх немає, буде запропоновано перейти до логу з усіма правилами, які існували для цього партнера.

Критерії фільтрації та пошуку зберігаються при переході між табами "Активні" та "Лог".

1.1.1. Таблиця з правилами обнулення

Стовпці таблиці:

- "Тип" – виводиться локація, ID вебмайстра, email вебмайстра або назва групи вебмайстрів;
- "Виконується" – виводиться інформація про виконання правила обнулення, можливі значення:
○ Кожного місяця – виводиться число, на яке налаштовано правило обнулення;
○ Один раз – виводиться повна дата запланованого разового обнулення.
- "Сайт" – сайт, для якого налаштовано обнулення;
- "Офер" – ID та назва офера, для якого налаштовано обнулення;
- "Валюта" – валюта для правила обнулення;
- "Дата створення / Дата зміни" – дата створення та дата останньої зміни правила обнулення;
- "Створив / Змінив" – логін адміністратора, який створив/відредагував правило обнулення;
- "Коментар" – коментар, який був доданий при налаштуванні правила обнулення;
- Кнопки дій:
○ "Редагувати" – відкриває модальне вікно для редагування правила;
Для ручного обнулення кнопка "Редагувати" в стані disable.
○ "Лог" – відкриває лог подій за конкретним правилом обнулення;
○ "Видалити" – відкриває модальне вікно для видалення правила.
Видаляючи правило, зберігається його лог.

## 2. Створення ручного (разового) обнулення

Функціонал ручного обнулення дозволяє створювати разове обнулення для вебмайстрів.

За кліком на кнопку "+ Створити ручне обнулення" відкривається модальне вікно для створення обнулення.

[image: https://d295evyo48.ucarecd.net/e2c44dbf-41c4-4614-bdd4-174e8e052610/image.png]

В модальному вікні задаються умови обнулення для вебмайстра. Додатково потрібно підтвердити обнулення.

[image: https://d295evyo48.ucarecd.net/578e0fb5-a9c4-485b-9ea6-f2dbe36d78ac/Group_12.png]

Якщо не вказати Сайт, Офер та Валюту, то у вебмайстра обнулиться негативний баланс за всіма оферами.

Негативний баланс вебмайстра буде обнулений одразу після підтвердження у формі – натискання кнопки "Обнулити".

Разове обнулення НЕ записується в таблицю.

## 3. Створення правила обнулення

Функціонал автоматичного обнулення дозволяє налаштовувати правила для щомісячного обнулення негативного балансу.

За кліком на кнопку "+ Створити правило" відкривається модальне вікно для створення нового правила.

[image: https://d295evyo48.ucarecd.net/73c454c6-3801-42a9-8649-d5d42ad62a8f/screencast_2025-07-24_14-50-11.gif]

В модальному вікні задаються умови обнулення для вебмайстра. Правило можна створити для вебмайстра, локації або групи вебмайстрів.

Можливість вибрати групу з'являється після вибору локації.

Якщо вибрати групу, то правило обнулення буде діяти лише для вибраної групи в рамках локації.

Для "ДАТИ СПРАЦЮВАННЯ" обираємо дату щомісячного спрацювання. Або ставимо правило на разове обнулення (конкретна дата).

Запити на обнулення негативних балансів виконуються автоматично щодня о 12:00 за UTC+0. Якщо запит зроблений до цього часу, він буде виконаний в той самий день.

Якщо запит на обнулення був зроблений пізніше, потрібно створити ручне (разове) обнулення.

3.1. Флоу налаштування правила обнулення

У відкритому модальному вікні обираємо вебмайстра, якому потрібно обнулити баланс. Проставляємо сайт, офер, валюту. Вводимо конкретну дату (для обраного типу спрацювання). Заповнюємо поле з коментарем (необов'язкове поле).

За кліком на кнопку "Створити" з'являється модальне вікно підтвердження з інформацією/умовами обнулення.

Успішно створене правило показане у табі "АКТИВНІ ПРАВИЛА".

Якщо для правила вибрано "31-ше число кожного місяця", і, наприклад, в місяці немає 31-го числа, то правило спрацює в останній день місяця.

3.2. Редагування правила обнулення

Структура модального вікна редагування схожа на модальне вікно для створення правила обнулення. Відмінність полягає у виведенні інформації про те, для кого було створено це правило: вебмайстер, група вебмайстрів чи локація.

При збереженні будуть відредаговані умови правила обнулення негативного балансу.

## 4. Таб "ЛОГ"

Дії з правилами обнулення та спрацювання обнулень логуються в окремому табі подій.

Таб "ЛОГ" розташований праворуч від табу "АКТИВНІ ПРАВИЛА".

Посилання на сторінку: https://aff.ltd/admin/new/negative-balance-rules/log

[image: https://d295evyo48.ucarecd.net/2bf7ac4f-a36d-464e-8579-100ee10cb7d4/Group_13.png]

В лог записуються події:

- Успішне створення ручного (разового) обнулення;
- Створення правила обнулення;
- Спрацювання правила обнулення;
- Редагування правила обнулення;
- Видалення правила обнулення.

Окремо можна вибрати сортування за типом подій:

- Правила обнулень;
- Ручні обнулення;
- Дії над правилами.

[image: https://d295evyo48.ucarecd.net/984276fa-70aa-44d8-93c0-721db9911079/image.png]

Обраний тип подій зберігається для сторінки логу.

4.1. Кожна подія виведена в окремій картці.

У картці події зліва виводиться поточний стан, справа – попередній. Стан відрізняється заливкою фону.

Створення та Видалення правила → без заливки.

4.2. Лог за конкретним правилом

Для кожного правила є окремо виведений лог подій. Перейти на сторінку можна через кнопку дій "Лог".

[image: https://d295evyo48.ucarecd.net/ceaeff23-d1d9-472c-8e13-ff60df461896/Group_13.png]

## 5. Тригерні розсилки по функціоналу обнулення негативних балансів

5.1. CRM Trigger: Players NGR <-10k

Розсилка відправляється партнерам з великими програшами (<$ -10k на балансі) і для яких налаштовано автоматичне правило обнулення негативних балансів (NNCO).

У сповіщенні повідомляється про великі програші (мінус у вебмайстра), при цьому вимикається правило обнулення першого числа місяця.

Алерт відправляється всім гравцям, які прийшли через RevShare або Hybrid програми, і у яких за поточний календарний місяць NGR менше або дорівнює -10k USD або EUR, або -1 000 000 RUB.

Сповіщення відправляється щопонеділка та першого числа кожного місяця о 6:00 за UTC+0.

5.2. CRM Trigger: Negative balance rule is blocked

Розсилка відправляється за вебмайстрами, у яких спрацює "Автоматичне вимкнення правила обнулення".

Автоматичне вимкнення правила обнулення для вебмайстрів налаштовано на перше число кожного місяця о 5:00 (UTC+0) за наступних умов:

- у вебмайстра є активне правило обнулення;
- на перше число місяця за попередній місяць у вебмайстра є гравець, у якого сума NGR < -10 000 USD (EUR або 1 000 000 RUB).

Сповіщення відправляється один раз на місяць.

Сповіщення відправляється в день вимкнення правила обнулення балансу (перше календарне число місяця) о 6:00 за UTC+0.
