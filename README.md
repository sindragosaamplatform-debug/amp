# aff.ltd support bot — proof of concept

Чат-бот підтримки B2B-платформи: відповідає командам партнерських програм так
само, як це роблять менеджери — знаходить потрібну статтю в довідковому центрі
[help.aff.ltd](https://help.aff.ltd/uk), веде по кроках і завжди дає посилання.

```
scrape_help.py  ──┐
  довідковий центр │──> kb-uk/  ──> kb.py ──┬── kb_mcp.py   (MCP-сервер для Claude Code)
ingest_cases.py ──┘   2547 записів   пошук  └── bot.py ──> app.py + static/  (веб-UI)
  кейси з чатів
```

**Два джерела.** Довідковий центр (68 статей) — те, на що бот посилається:
`admin-panel` як основний (інструменти самого клієнта), `aff-area` — коли
питання про кабінет вебмайстра. `team-cases` (2479 кейсів із робочих чатів за
2025–2026) — контекст: упізнати проблему й зрозуміти, коли потрібна команда
платформи; дані між клієнтами не переносяться.

Кейси **не виводяться в каталог** — їх тисячі, перелік роздув би системний
промпт. У каталозі лише лічильники за темами, самі кейси знаходить `kb_search`.

## Що всередині

| Файл | Призначення |
|---|---|
| [scrape_help.py](scrape_help.py) | Скрейпер HelpCrunch-бази: статті → чистий текст |
| [ingest_cases.py](ingest_cases.py) | CSV із запитами команд → кейси з вирізаними ідентифікаторами |
| [kb-uk/](kb-uk) | Корпус: `admin-panel` (50), `aff-area` (15), `additional-resources` (3), `team-cases` (2479) |
| [kb.py](kb.py) | Завантаження корпусу, каталог-роутер, повнотекстовий пошук |
| [kb_mcp.py](kb_mcp.py) | MCP-сервер (stdio): `kb_search`, `kb_get_article`, `kb_list` |
| [bot.py](bot.py) | Агент: системний промпт, tool-loop, стрімінг |
| [app.py](app.py) | ASGI-застосунок (FastAPI): веб-UI, SSE, гейт за кодом |
| [static/](static) | Чат-інтерфейс і сторінка входу |
| [vercel.json](vercel.json) | Конфіг деплою |

**Без векторної бази.** Каталог 68 статей (~5k токенів) лежить у системному
промпті як роутер і кешується (prompt caching), а модель читає **статтю цілком**
через `kb_get_article`. Пошагові інструкції не ріжуться на чанки — це головна
причина, чому такий підхід точніший за класичний RAG на цьому обсязі.

## Запуск

Усі команди — з кореня проєкту.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

Веб-UI (http://127.0.0.1:8765):

```bash
.venv/bin/python -m uvicorn app:app --reload --port 8765
```

Той самий бот у терміналі:

```bash
.venv/bin/python bot.py
```

Перевірити базу без моделі:

```bash
python3 kb.py search "постбек keitaro"
```

## MCP-сервер + Claude Code (без API-ключа)

Найшвидший спосіб побачити бота в дії — не піднімати сервер, а відкрити Claude
Code у цій папці: MCP-сервер уже прописаний у [.mcp.json](.mcp.json), а персона
бота — у слеш-команді `/aff-support`.

1. Новий чат Claude Code у кореневій папці проєкту
2. Підтвердити підключення MCP-сервера `aff-kb`, коли він запитає дозвіл
3. `/aff-support` — далі просто питати як клієнт

Ключ тут не потрібен: клієнтом виступає сам Claude Code. Той самий сервер
підключається будь-яким іншим MCP-клієнтом — менеджери можуть тримати базу
під рукою у себе.

Сервер написаний на голій стандартній бібліотеці (JSON-RPC 2.0 по stdio), бо
офіційний MCP SDK вимагає Python 3.10+, а в системі 3.9. Працює на будь-якому
системному `python3` — venv для нього не потрібен.

Персона бота лежить в одному файлі [support_prompt.md](support_prompt.md): його
читає і `/aff-support`, і `bot.py`, тож обидва поводяться однаково.

## Кейси з робочих чатів

Вивантаження CSM-дашборду (`Дата, Чат команди, Категорія, Тип запиту, Питання,
Відповідь, Статус, Jira`) перетворюється на кейси:

```bash
python3 ingest_cases.py "~/Downloads/CSM DASHBOARD"*.csv
```

Приймає всі вивантаження одразу: назви колонок різняться між місячними та
квартальними аркушами, а квартальні "All" дублюють місяці — однакові звернення
відкидаються за текстом питання.

Скрипт вирізає те, що не повинно дійти до клієнта: e-mail, IP, ID партнерів,
сторонні посилання, Jira-ключі; ніки в діалозі замінює на `[команда]` / `[AMP]`.
Оригінальний CSV у проєкт не копіюється. Кожен кейс має банер «внутрішнє», а
категорія помічена в каталозі — правила поводження з нею описані в
[support_prompt.md](support_prompt.md).

## Оновлення бази

Статті живі — раз на добу варто перескрейпити:

```bash
for c in admin-panel aff-area additional-resources; do python3 scrape_help.py --url "https://help.aff.ltd/uk/$c" --out "kb-uk/$c" --keep-images; done
```

`--keep-images` лишає маркери `[image: URL]` — скріншоти на публічному ucarecdn,
бот показує їх клієнту, коли той «не бачить кнопку».

**Після будь-якого оновлення корпусу перезберіть пак:**

```bash
python3 kb.py pack
```

`kb-uk/_pack.json` — весь корпус одним файлом. Якщо він є, база вантажиться з
нього (0.11 с проти 0.39 с на 2547 файлах) — це помітно на холодних стартах
serverless. У бандл Vercel їдуть тільки пак і код: `.md` виключені через
`excludeFiles`. Пак закомічений, тому забути його оновити = задеплоїти стару
базу; дату збірки видно в `python3 kb.py` та в `/api/kb`.

## Налаштування

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `AFF_BOT_MODEL` | `claude-opus-4-8` | Модель |
| `AFF_BOT_EFFORT` | `medium` | Глибина міркувань: `low`…`max` |
| `ACCESS_CODE` | порожньо | Код доступу до веб-UI; порожній = без гейта |
| `KB_ROOT` | `./kb-uk` | Корінь корпусу (напр. `kb-ru`) |

## Межі, зашиті в промпт

- Відповідає **тільки** за прочитаними статтями; не вигадує кнопки й статуси.
- Завжди дає посилання, у локалі діалогу (`/uk/`, `/ru/`, `/en/`).
- На баг просить дані для перевірки: посилання, скріншот, ID, час, кроки відтворення.
- Не обіцяє виплати, ставки й рішення по акаунтах — це до менеджера.
- Не питає паролі, 2FA-коди, токени.
- Не переносить дані між клієнтами: кейс однієї команди не переказується іншій.

## Деплой на Vercel

Застосунок stateless: історію діалогу тримає браузер і надсилає назад щоходу,
тому будь-який інстанс обслуговує будь-який запит.

- точка входу — `app.py`, змінна `app` (ASGI), Python 3.12 з `.python-version`;
- залежності — `requirements.txt`;
- `vercel.json` — `maxDuration` 120 с, регіон `fra1`, виключення зайвого з бандла;
- змінні оточення в проєкті: `ANTHROPIC_API_KEY` (Production + Preview),
  `ACCESS_CODE`, за бажанням `AFF_BOT_MODEL`.

У бандл їде `_pack.json` (~6.7 МБ) замість 2547 файлів — ліміт для Python 500 МБ.

## Чого ще немає (наступні кроки)

1. **Оцінка.** 30–50 реальних питань з чату з правильними відповідями — інакше
   не видно, чи правка промпту покращила, чи зламала.
2. **Канал.** Зараз власний UI; далі — HelpCrunch API або Telegram, з передачею
   діалогу живому менеджеру.
3. **Ідентифікація партнера.** Бот не знає, хто питає; персональні дані (баланс,
   статус оферу) поза базою знань.
